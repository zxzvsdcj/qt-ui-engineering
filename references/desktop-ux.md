# Desktop UX

## Optimize repeated work

Desktop applications support sustained, multi-step work. Prefer stable spatial memory and efficient input over landing-page simplicity.

- Menus expose the complete command set and conventional shortcuts.
- Toolbars expose frequent, context-appropriate commands.
- Context menus accelerate object-specific actions but never provide the only access path.
- Status bars show selection counts, mode, connection, progress, and background state.
- Splitters, docks, tabs, trees, tables, and inspectors support comparison and multi-panel workflows.
- Keyboard shortcuts supplement visible controls; they do not replace discoverability.

## Window behavior

- Preserve useful geometry, splitter state, columns, and workspace layout when appropriate.
- Respect platform conventions for dialog buttons, menus, focus, file selection, and window controls.
- Make minimum size reflect actual usability, not the initial design canvas.
- Keep destructive actions separated from routine actions and provide recovery where possible.

## Data-heavy surfaces

- Use Model/View and incremental updates for large collections.
- Keep column labels, sorting, filtering, selection, and active scope obvious.
- Provide copy/export or details for truncated values.
- Show empty, loading, stale, and partial-error states without losing navigation context.

## Review

Measure task steps for the most frequent workflows. Tab through the interface, exercise shortcuts and context menus, resize the window, restore saved state, and verify that menus/toolbars/status surfaces remain coherent across modes.
